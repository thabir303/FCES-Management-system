\noindent This appendix sits outside the paper's page limit, per the handbook's placement of
appendices after the main publication and their exemption from the template. It carries two
things the main paper's ten pages have no room for: the evidence that the delivered system
satisfies the client brief, and the exhibits from Section~\ref{sec:exhibits} that did not fit
the paper.

\textbf{No user interface was built.} \texttt{system/web} is an empty placeholder
(\texttt{.gitkeep} only) -- the scope fence in the project plan named a dashboard, a user
administration UI, and an audit-browsing UI explicitly out of scope, and no other interface was
substituted for them. Every claim below about the delivered system is therefore evidenced at the
API level: real HTTP requests and real HTTP responses against a live Postgres instance, not
screenshots of a screen that does not exist. Stating this once, plainly, is the point --
its absence should not have to be discovered by a reader.

\section{Architecture}
\label{sec:architecture}

\begin{figure}[h]
\centering
\includegraphics[width=0.85\linewidth]{results/figures/A1_architecture.pdf}
\caption{The research library, the API, and the database, with the single import boundary
between the first two. \texttt{grep -r "import fcesreg" system/} returns exactly
\texttt{system/api/src/fcesapi/services/pipeline.py\allowbreak{}} -- this diagram draws that grep result,
not an aspiration.}
\end{figure}

\texttt{fcesreg} is pure Python over pandas DataFrames and numpy arrays: no database access, no
network access outside its own \texttt{ingest\_\allowbreak{}*} and \texttt{llm} modules, and no import from
\texttt{system/}. \texttt{system/api} adapts between HTTP/SQLAlchemy and those DataFrames in
exactly one file, so the paper's claim that ``the pipeline is deployed inside the asset
management system delivered to FCES'' is a statement about this one crossing point, checkable
by a single \texttt{grep}, rather than a claim taken on trust.

\section{API-Level Evidence}
\label{sec:api-evidence}

Every body below is quoted from \texttt{results/\allowbreak{}appendix\_\allowbreak{}evidence.json},
produced by \texttt{capture\_\allowbreak{}appendix\_\allowbreak{}evidence.py} (under
\texttt{system/\allowbreak{}api/\allowbreak{}src/\allowbreak{}fcesapi/\allowbreak{}scripts/\allowbreak{}})
against a live Postgres instance through the same code path (\texttt{TestClient} over the real
FastAPI app, no auth faking, the real fitted \texttt{fcesreg} pipeline) the test suite itself
exercises. The script
seeds one asset, uploads a two-row CSV in which one row is an exact textual duplicate of that
asset, resolves both rows, commits the batch, and reads back the result -- then deletes every
row it created, in its own \texttt{finally} block, verified afterward to leave the database's
user/asset/batch counts unchanged. Nothing below is illustrative.

\subsection{A bulk import request and response}

\begin{verbatim}
POST /api/v1/imports
files: assets.csv, 2 rows:
  Centrifuge 5424 <tag>, Bench top centrifuge, Eppendorf
  Autoclave Pro 200 <tag>, Steam steriliser, Getinge

--> 201
{
  "batch_id": 57,
  "detected_columns": ["Equipment Name", "Description", "Make"],
  "sample_rows": [
    {"Equipment Name": "Centrifuge 5424 <tag>",
     "Description": "Bench top centrifuge", "Make": "Eppendorf"},
    {"Equipment Name": "Autoclave Pro 200 <tag>",
     "Description": "Steam steriliser", "Make": "Getinge"}
  ]
}
\end{verbatim}

\subsection{A flagged duplicate in the review queue, with confidence and competing candidate}

The centrifuge row above is textually identical to an asset already in the register
(\texttt{id: 322}, seeded moments earlier in the same run), and the real \texttt{tfidf}-based
matcher -- not a stub -- scores it accordingly:

\begin{verbatim}
GET /api/v1/imports/57/rows  -->  row id 102:
{
  "dedup_decision": "duplicate",
  "dedup_score": 0.8301,
  "dedup_candidate_asset_id": 322,
  "class_cpv_code": "4293",
  "class_score": 0.669,
  "class_alternatives": [
    {"code": "3800", "score": 0.0529},
    {"code": "4800", "score": 0.0355},
    {"code": "3300", "score": 0.0251}
  ],
  "evidence": {
    "dedup": {"method": "tfidf_char_ngrams",
              "matched_ngrams": ["cen","ent","ntr","tri","rif","ifu","fug","...]},
    "classification_floor": 0.4276
  },
  "route": "review"
}
\end{verbatim}

\subsection{A review decision and the six logged fields it writes}

The reviewer confirms the automated duplicate call. \texttt{ReviewDecision} joins to the row
above by \texttt{import\_\allowbreak{}row\_\allowbreak{}id} rather than duplicating \texttt{dedup\_\allowbreak{}score}/\texttt{class\_\allowbreak{}score}
onto itself:

\begin{verbatim}
POST /api/v1/imports/57/rows/102/resolve
{"action": "accept", "decision_type": "dedup", "seconds_taken": 6}
--> 200 {"row_id": 102, "action": "accept"}

the row it wrote:
{
  "id": 14,
  "import_row_id": 102,
  "actor_id": 1422,
  "decision_type": "dedup",
  "action": "accept",
  "chosen_value": null,
  "seconds_taken": 6,
  "at": "2026-08-27T03:34:40.230457+00:00"
}
\end{verbatim}

\subsection{The resulting asset}

The autoclave row was genuinely novel (\texttt{dedup\_\allowbreak{}decision} not \texttt{duplicate}); on
commit it -- and only it -- is written as a new asset, auto-classified by the same fitted
pipeline:

\begin{verbatim}
POST /api/v1/imports/57/commit  -->  200 {"batch_id": 57, "assets_created": 1}

GET /api/v1/assets/323:
{
  "id": 323,
  "asset_tag": "FCES-000323",
  "name": "Autoclave Pro 200 <tag>",
  "description": "Steam steriliser",
  "manufacturer": "Getinge",
  "cpv_code": "3319",
  "created_at": "2026-08-27T03:34:40.244561Z"
}
\end{verbatim}

The duplicate-confirmed centrifuge row is, correctly, not written a second time: a confirmed
duplicate is never committed as a new asset.
