# Rules for runners, configs and results

**Run identity.** `run_id = <script>-<UTC yyyymmddTHHMMSS>-<git short sha>-<sha256(config)[:8]>`,
from `runs.new_run_id(script, config_path)`. Identical config bytes always produce an identical
final component, which is what makes two runs comparable at a glance.

**Every run writes four artefacts** via `runs.write_run`: `params.yaml`, `metrics.json`,
`env.json`, and `predictions.parquet` when predictions exist. **No per-run ledger file.**

**Capture the environment before the work, not after.** Call `capture_env()` at the start and pass
it to `write_run(..., env=env)`; capturing afterwards records the state the run finished in.

**One global ledger** at `results/ledger.jsonl`, every row carrying `run_id`. Spend aggregates
across runs — a `cap_usd` guard is meaningless against a fresh per-run ledger — and cache hits span
them, so a run costing $0.00 because an earlier run paid is only interpretable against a shared
ledger. Appends are atomic: open `"a"`, one `write()` of a single line ending `\n`.

**A dirty git tree marks the run and `make_tables.py` refuses it.** Commit, then run. A number that
cannot be traced to a commit does not go in the paper. `--allow-dirty` exists for local inspection
only and its output must not ship.

**Runners are config-driven and never take tuning flags.** Parameters live in
`research/configs/*.yaml`, which is committed. A flag that changes a measured outcome is a way to
tune without leaving a trace.

**Select on dev, never on test.** Thresholds, operating points and model fitting use the
development partition; `splits.py` is the only source of the partitions. **Every table carries its
`run_id`**, so any figure traces back to the code and environment that produced it.

**Never edit `results/tables/*` by hand.** They are generated by `make_tables.py`; a PreToolUse hook
blocks writes to them. Change the builder, then `make tables`.

**A disappointing measurement is a finding.** Report it as measured. Do not tune, refit, or narrow a
sweep so a number reads better; if the result invites that, raise it with the supervisor instead.
